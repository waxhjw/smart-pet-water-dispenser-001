# 007 分段测试与记录

测试固件唯一入口：`-SpecTest007Retry30s`；烧录文件为 `firmware/target/py32f002b/build-spec-test007-retry30s/sp01_py32f002b.hex`。先按构建文档生成并检查它确实存在，再执行以下步骤。固件和 ELF 必须来自同一构建。

## 准备

- 使用无进水、无明显损坏的板，确认电池极性、供电、SWD 和板卡版本；负载放在有水且装配位置正确的环境。
- 新板先运行 `-BenchNoPump` 检查 PB2 关泵和输入采样，再测试 007。
- 准备满水、预警附近、保护条件三种状态；禁止长时间无水运行。
- 记录 Git 提交、profile、HEX SHA-256、板号、供电、电池实测电压、采样值和灯色。异常时立即使用已经验证的停止路径，必要时断开 Type-C 和电池。

## 操作、观察和通过标准

| 测试目标 | 操作与等待 | 预期与通过标准 |
| --- | --- | --- |
| 本地开关机 | 长按触摸约 3 秒，松开后再重复 | 达到时长有开关机反馈，关机停泵；持续按住不应反复切换 |
| Type-C 正常出水 | 满水、仅 Type-C，等待识别稳定 | 进入连续出水，采样正常，无假缺水保护 |
| 单独电池启动 | 仅电池上电，先观察，再长按开机 | 初始关机；开机后待机；雷达等待约 5 秒，再持续无人约 2 秒后才允许新触发 |
| 雷达定时 | 完成待机准备，进入感应区一次，记录出水时间 | 约 15 秒停泵，进入约 180 秒冷却；高电平持续时不能无限续水 |
| 带电切换 | 电池保持连接，Type-C 连续出水时拔掉线；满水和预警水量各做 5 次 | 供电去抖后约 1 秒切回电池待机并停连续出水；新雷达触发需等初始化/布防；正常绿灯、预警绿单闪，夜间/低电量和故障优先级另记 |
| 切回 Type-C | 电池待机时插回 Type-C，等待约 1 秒 | 供电稳定后恢复 Type-C 模式；缺水保护仍锁定时不得直接解除 |
| 低水位预警 | 泵启动后等待约 6 秒，再观察 2 个约 1 秒窗口的 PA3 均值 | 连续 ≤585 mV 出现约每秒 0.1 秒单闪；预警本身不强制停泵；颜色按板上实测记录 |
| 缺水停泵 | 在可控条件下使采样 ≤420 mV，观察启动忽略期后的 3 个完整窗口 | 停泵、缺水报警闪烁及一次蜂鸣；须另确认实物报警确为红色 |
| 定时复测 | 保持保护条件并记录至少两次试泵 | 约每 30 秒试泵，每次最长 5 秒；保护不被普通供电切换绕过 |
| 补水恢复 | 保护期间补水、保持线圈对齐，等待下一次试泵 | 忽略前 1 秒后，>625 mV 连续两个窗口恢复；无需手动重启 |
| 低电压保护 | 使用受控供电和已确认的测试方法缓慢改变电池电压 | 低电量提示与临界低压停机符合阈值；不要靠反复深放真实锂电池制造条件 |
| 异常及复位 | 检查 Type-C、电池、复位和缺水条件的组合；先备好停机路径 | 初始化输出先关，后续启动按当前 profile 定义；记录看门狗和传感器未知时的实际行为，不笼统宣布通过 |

## 失败时收集什么

记录拔线前后灯色和闪烁节奏、持续出水时长、雷达活动、CHRG/DONE 电平、电池端电压与软件采样值、PA3 均值、状态及供电枚举。只有灯色和现象时不能直接断言具体根因。

优先检查：是否选对 007 HEX 与同次 ELF；供电判断是否切换；状态是否进入电池待机；PB2 的实际电平是否跟随停泵请求；再检查进水漏电、回灌、驱动和采样电路。一次只改一个变量。
